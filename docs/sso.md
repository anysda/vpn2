# SSO в панель через Authentik (OIDC)

Панель умеет отдавать вход внешнему OIDC-провайдеру. Проверено на
[Authentik](https://goauthentik.io/); других IdP не пробовали, но обработчик
общий — нужен только discovery-документ.

Выключено по умолчанию: логин и пароль, TOTP, rate-limit. Включается и
настраивается в панели («Настройки» → «Вход через Authentik», `/settings`) и
действует сразу, без передеплоя. Блок `sso:` в `config.yaml` только засевает
настройки при первой установке: после первого сохранения в «Настройках» главнее
панель, повторный деплой их не затирает (они лежат в
`/etc/anysda/sso-runtime.json` на entry-ноде).

---

## Что получается в итоге

- При `auto_redirect: true` неавторизованного человека сразу уносит в Authentik — формы он не видит вообще.
- Обратно возвращается уже с сессией панели.
- Пароль **не удаляется**, а прячется: форма живёт по адресу
  `https://<домен>/login?direct=1`. Это break-glass на случай, когда Authentik
  недоступен, — и он не зависит от Authentik.
- Панель **никогда** не заводит учётку из IdP. Вход привязывается к уже
  существующей учётке и только по явному списку.

## Модель доступа (почему так строго)

В этом флоте каждый пользователь Authentik — суперюзер. Если бы панель заводила
учётку по факту успешного входа, любой человек из IdP становился бы её админом.
Поэтому:

1. **Связка по `sub`** — uuid пользователя в IdP (`sub_mode: user_uuid` у
   провайдера). Не по имени: имя человек меняет сам. Не по почте: почта в панели
   и в IdP расходится, а auto-link по почте — вектор захвата (завёл в IdP юзера
   с чужой почтой → вошёл под чужим).
2. **Явный allow-список** («Кого пускать» в «Настройках», `sso.allowed_subs` в
   `config.yaml`). Пустой = не войдёт никто: панель такое не сохраняет, стадия
   деплоя падает заранее, чтобы это не выяснилось на живом входе.
3. **Первый вход только привязывает**, не создаёт. Нет локальной учётки —
   отказ (`sso_no_local_user` при явном логине, `sso_ambiguous` без него), а не «сейчас заведём».

## Порядок подключения

Порядок именно такой: сначала провайдер в IdP, потом uuid, и только потом
включение входа. Без провайдера и разрешённого uuid вход не состоится;
новые учётки обработчик SSO не создаёт.

### 1. Завести OIDC-провайдер и приложение в Authentik

Нужны:

| поле | значение |
|---|---|
| client type | confidential |
| client id | `vpn2` |
| redirect uri | `https://<домен панели>/auth/authentik`, matching mode **strict** |
| grant types | `authorization_code`, `refresh_token` |
| sub mode | `user_uuid` |
| scopes | `openid`, `profile`, `email` |

⚠️ У провайдера, созданного **не** через веб-форму (blueprint, API), поле
`grant_types` приезжает пустым, и вход падает с `invalid_request / The request
is otherwise malformed`. Задавать явно.

### 2. Узнать `sub` пользователя

`sub` при `sub_mode: user_uuid` — это поле `uuid` пользователя в Authentik
(не `pk`, не имя). В API:

```bash
curl -s -H "Authorization: Bearer <ak-token>" \
  'https://<authentik>/api/v3/core/users/?username=<логин>' \
  | jq -r '.results[0].uuid'
```

### 3. Включить в настройках панели

Войти паролем, открыть «Настройки» → «Вход через Authentik» и заполнить:

| поле | что вписать |
|---|---|
| адрес Authentik | `https://auth.example.com` или сразу discovery URL |
| slug приложения | slug приложения в Authentik (по умолчанию `vpn2`) |
| client_id, client_secret | из провайдера; сохранённый секрет целиком не показывается, пустой client_secret = оставить прежний, client_id обязателен |
| кого пускать | `<uuid>` или `<uuid>:<логин в панели>` через запятую |
| адрес возврата | подставлен от адреса панели; тот же вписать в redirect uri провайдера |
| подпись кнопки, бесшовный вход | по вкусу |

Discovery собирается как
`{адрес}/application/o/{slug}/.well-known/openid-configuration`; если IdP не
Authentik — вписать discovery URL целиком. Кнопка «Проверить» читает его с
entry-ноды. «Сохранить» применяет сразу: выйти и войти уже через Authentik.

Форма не сохраняет то, после чего в панель никто не войдёт: SSO без
client_id, client_secret или с пустым «кого пускать», логин из списка, которого
нет в панели, адрес возврата не по HTTPS, выключение пароля без SSO.

### Или засеять из `config.yaml` при установке

```yaml
sso:
  enabled: true
  base_url: https://auth.example.com    # адрес IdP
  app_slug: vpn2                        # slug приложения в Authentik
  client_id: vpn2
  client_secret: "<секрет OIDC-клиента>"
  allowed_subs: "<uuid>"                # или "<uuid>:<логин в панели>", через запятую
  auto_redirect: true                   # true — формы не видно вообще
  password_login: true                  # пароль спрятан, но ЖИВ
  label: Authentik
```

`redirect_uri` стадия строит сама из `panel.domain`. Выкатить:

```bash
./deploy.sh 30-frontend ru
```

Стадия пересоздаёт контейнер панели и настраивает Caddy. Стадии WireGuard,
OpenVPN, IKEv2 и sing-box не запускаются; при старте панель синхронизирует
клиентские конфиги из БД.
Работает, пока настройки ни разу не сохраняли в панели: дальше блок `sso:`
не применяется, править в «Настройках».

## Требования и ограничения

- **Только HTTPS** (`panel.domain` обязателен для засева при деплое). Стадия 30
  включает `Secure` для cookie при заданном домене и падает, если SSO включён
  без домена. Профиль не сохраняет адрес возврата не по HTTPS; флаг `Secure`
  задаётся окружением контейнера (`NUXT_SESSION_COOKIE_SECURE`).
- **Панель должна дотягиваться до IdP по сети** — discovery и обмен кода на
  токен идут с самой entry-ноды, а не из браузера.
- Локальный TOTP при входе через SSO не спрашивается: второй фактор — забота
  IdP. На парольном break-glass-входе TOTP работает как работал.
- Выйти из панели, пока жива сессия в самом Authentik, «насовсем» нельзя:
  кнопка «Выйти» кладёт человека на `/login?direct=1`, откуда автоматического
  возврата в IdP уже нет.

## Break-glass

| ситуация | что делать |
|---|---|
| Authentik лежит / SSO сломан | `https://<домен>/login?direct=1` → логин и пароль |
| забыт первоначальный пароль | `cat /etc/anysda/admin-password.txt` на entry-ноде; смена пароля в профиле этот файл не обновляет |
| надо выключить SSO совсем | «Настройки» → включить «Оставить вход по паролю» → выключить «Вход через Authentik» → «Сохранить» |
| надо сбросить настройки SSO из панели | на entry-ноде `rm -f /etc/anysda/sso-runtime.json && docker restart anysda-vpn2` — вернутся настройки из env контейнера, заданные последним деплоем; без client_secret SSO и авторедирект выключены, парольный вход доступен независимо от `NUXT_SSO_PASSWORD_LOGIN`. При полном включённом SSO для парольного входа нужен `NUXT_SSO_PASSWORD_LOGIN=true` |

⚠️ Выключенный «вход по паролю» рубит его наглухо — **вместе с break-glass**.
Профиль даёт выключить его только сессии, вошедшей через Authentik, отдельным
сохранением (остальные поля SSO не меняются) и при живом discovery.

## Коды ошибок на форме

| код | что значит |
|---|---|
| `sso_off` | рубильник выключен или клиент недонастроен |
| `sso_failed` | не удалось начать вход через IdP; ошибки callback возвращаются кодами better-auth, например `state_mismatch` |
| `sso_not_allowed` | вход прошёл, но `sub` не в `allowed_subs` |
| `sso_no_local_user` | в панели нет учётки с явно указанным логином |
| `sso_ambiguous` | без явного логина найдено не ровно одна учётка — нужен формат `<sub>:<логин>` существующей учётки |
| `sso_already_linked` | учётка панели уже привязана к другому `sub` |

Подробности каждого отказа — в логе панели (`docker logs anysda-vpn2`), наружу
отдаётся только код.

## Как это устроено в коде

| файл | что делает |
|---|---|
| `app/server/routes/auth/authentik.get.ts` | точка входа и callback `/auth/authentik` |
| `app/server/utils/auth.ts` | better-auth: провайдер `authentik` (genericOAuth), сессии |
| `app/server/utils/sso.ts` | настройки (`/etc/anysda/sso-runtime.json`, засев из env), allow-список, привязка по `sub`, отказы |
| `app/server/api/admin/sso.*` | настройки из панели: чтение, сохранение с проверками, «Проверить» |
| `app/app/pages/settings.vue` | карточка «Вход через Authentik» в «Настройках» |
| `app/app/middleware/auth.global.ts` | авторедирект неавторизованного в IdP |
| `app/app/pages/login.vue` | форма break-glass, кнопка входа, коды ошибок |
| `infra/scripts/30-frontend.sh` | env контейнера (засев) + защёлка «SSO без HTTPS» |
| `infra/lib/config2env.py` | блок `sso:` из `config.yaml` → `ru.env` (засев) |

Протокол ведёт [better-auth](https://www.better-auth.com/) (плагин
`genericOAuth` с discovery): `state`, PKCE и обмен кода — его, свой код только
решает, кого пускать. Адрес возврата у провайдера прежний, `/auth/authentik`:
он пересылает код в колбэк библиотеки.

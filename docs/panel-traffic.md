# Панель: скорость клиентов, периоды трафика, диаграммы нод

Что показывает панель о трафике, откуда берутся цифры и как они считаются.
Все границы суток — **00:00 МСК** (UTC+3 круглый год, `server/utils/msk-day.ts`),
одни и те же для клиентов и нод.

## 1. Текущая скорость клиента

В списке клиентов слева у клиентов **в сети** в нижней строке карточки —
`↓ x ↑ y Мбит/с`: текущая скорость по всем устройствам клиента (↓ — к клиенту,
↑ — от клиента).

**Откуда.** `GET /api/clients/traffic` (панель опрашивает раз в 3 с) отдаёт к
каждому клиенту `rxBps` / `txBps` (байт/с). Считает `server/utils/client-rates.ts`
по тем же накопительным счётчикам, что и минутный сборщик трафика
(`sampleWg` / `sampleOvpn` / `sampleIkev2` из `traffic-collector.ts`):

- снимок счётчиков не чаще раза в 2 с — несколько открытых вкладок не гоняют
  `wg show` пачкой;
- скорость по каждому счётчику (`устройство:протокол`, у IKEv2 — `устройство:SA`)
  считается **по смене значения**: статус IKEv2 обновляется раз в 10 с, и дельта
  на каждом 3-секундном опросе давала бы «0 → пик»;
- сглаживание EWMA ~6 с — чтобы список, отсортированный по скорости, не прыгал;
- счётчик без изменений дольше 12 с — простой (0); сброс счётчика (рестарт
  службы) — новая база без скачка; отключившееся устройство забывается.

Поэтому скорость у только что затихшего клиента гаснет за несколько секунд, а
не мгновенно.

**Сортировка списка** — на лету, при каждом опросе: текущая скорость (только у
клиентов в сети) → трафик за сутки → трафик за всё время → имя. Чтобы список
не дёргался:

- место под скорость держится у всех клиентов в сети (в простое — невидимое,
  ширина фиксирована) — высота карточки не скачет;
- у контейнера списка `overflow-anchor: none` — scroll anchoring браузера не
  подкручивает прокрутку страницы вслед за переставленной карточкой;
- пока курсор мыши над списком, порядок заморожен (цифры обновляются), чтобы
  карточка не уехала из-под курсора; на тач-экранах не замораживается.

## 2. Период «Сутки / Вчера / Неделя»

Один селектор в блоке «ТОП клиентов» управляет **и ТОП, и всем трафиком нод в
«Мониторинге»** (общее состояние `useTrafficPeriod()` в `useClients.ts`).

| Период | Окно (МСК) |
|---|---|
| Сутки | с 00:00 сегодня до сейчас |
| Вчера | [00:00 вчера, 00:00 сегодня) |
| Неделя | с 00:00 шесть суток назад до сейчас (7 календарных суток) |

**Клиенты** — `GET /api/clients/top?period=day|yesterday|week`: суммы по
почасовым бакетам `device_traffic_hourly` в окне периода (`periodRange()` +
`periodTotalsByClient(since, until)` в `client-activity.ts`). Неверный период —
`400 invalid_period`.

**Ноды** — `GET /api/ops/nodes?period=…`: поля `trafficPeriod`, `rxPeriodBytes`,
`txPeriodBytes` (вместо прежних `rxTodayBytes`/`txTodayBytes`) — `increase()`
счётчиков WAN-интерфейса в VictoriaMetrics:

- сутки: окно = секунд с полуночи;
- вчера: окно `86400s` со сдвигом `offset <секунд с полуночи>`;
- неделя: окно = секунд с полуночи + 6 × 86400.

Считается только физический интерфейс (`lo`, `wg*`, `tun*`, `xfrm*`, `docker*`,
`veth*`, `br-*` исключены), иначе трафик entry задвоится. Кэш: сутки — 30 с,
неделя — 5 мин, вчера — до полуночи; на смене суток кэш сбрасывается.

## 3. Диаграмма трафика в карточке ноды

Внизу карточки каждой ноды (вместо прежней CPU-линии за ~2 мин; текущий CPU
остался цифрой) — столбцы по **выбранному периоду**:

| Период | Столбцы |
|---|---|
| Сутки | 24 часа с 00:00 МСК: прошедшие, текущий (полупрозрачный, онлайн), будущие — пусто |
| Вчера | 24 часа вчерашних суток |
| Неделя | 7 суток МСК, сегодня — онлайн |

На каждый час / сутки два столбца:

- **фиолетовый — пик скорости**: максимальная **средняя за минуту** скорость
  внутри часа (мгновенный 2-секундный всплеск не рисует ложный пик), большее из
  ↓/↑ — загрузка канала в нагруженную сторону;
- **голубой — объём**: ↓ + ↑ за час / сутки.

Ряды в разных единицах, поэтому каждый масштабируется к своему максимуму за
период. Наведение (на телефоне — тап) — подсказка: интервал по МСК, пик ↓/↑ в
Мбит/с, объём ↓/↑. Нет данных за час (нода лежала, VM не ответила, вне хранения
метрик) — серая риска, а не ноль. У карточки в состоянии warning диаграмма
красная, как и вся карточка.

**API** — `GET /api/ops/nodes/hourly?period=day|yesterday|week` (отдельно от
`/api/ops/nodes`, который опрашивается раз в 2 с; панель берёт его раз в 5 с):

```jsonc
{
  "period": "day",
  "unit": "hour",            // "day" у недели
  "nodes": [{
    "tag": "ru",
    "buckets": [{ "start": 1791579600, "end": 1791583200,
                  "rxBytes": 1.2e9, "txBytes": 1.1e9,
                  "rxPeakBps": 4.1e6, "txPeakBps": 3.9e6,
                  "current": false, "future": false }]
  }]
}
```

**Как считается** (`fetchTrafficBuckets()` в `server/utils/vm-client.ts`):

- полные часы — один `query_range` с шагом 3600 на выражение:
  - объём `sum by(instance)(increase(node_network_{receive,transmit}_bytes_total{WAN}[1h]))`;
  - пик `max_over_time(sum by(instance)(rate(…[1m]))[1h:30s])`;
  - точка `t` относится к часу `[t−1ч, t)`; кэш до смены часа (для каждого периода свой);
- текущий час — мгновенные запросы тех же выражений с окном «с начала часа», кэш 5 с,
  при сбое VM — последнее удачное значение (сбрасывается на смене часа);
- сутки недели собираются из часов: объём — сумма, пик — максимум.

Запросы дешёвые (десятки мс на холодном кэше); сумма столбцов совпадает с
итогом периода в той же карточке.

**Ограничение:** VictoriaMetrics хранит 7 дней (`-retentionPeriod=7d`) —
неделя укладывается впритык; на свежем entry (или после потери данных VM) часы
до начала истории метрик — серые риски.

## 4. Кнопка «AdGuard Home» по настраиваемому адресу

Кнопка в блоке DNS вела на `https://<хост панели>:3001`. Если UI AdGuard открыт
только изнутри VPN (IP entry исключён из `AllowedIPs` WireGuard, поэтому домен
entry идёт мимо туннеля даже с включённым VPN), нужен служебный адрес:

```yaml
panel:
  adguard_url: http://10.99.0.1:3080
```

`config.yaml` → `AGH_UI_URL` (`config2env.py`) → `NUXT_PUBLIC_AGH_UI_URL`
(стадия 30). Без ключа — как раньше.

## 5. Ночной бэкап не падает на «database is locked»

`anysda-backup.sh` снимал БД через `sqlite3 .backup` без ожидания блокировки, и
если ночной запуск совпадал с минутной записью панели — сразу падал
`database is locked`. Теперь `sqlite3 -cmd '.timeout 30000'` (и для
`PRAGMA schema_version`): ждёт снятия блокировки до 30 с.

# Служебный канал по Hysteria2 (замена WireGuard-mesh)

Статус: дизайн на согласование. Дата: 2026-09-23.

## Зачем

Сейчас служебная сеть между нодами — отдельный WireGuard-интерфейс `wgmgmt`
(подсеть `10.99.0.0/24`, стадия `05-mgmt-mesh`). По ней entry-нода из РФ
скребёт `node_exporter` каждого зарубежного экзита для VictoriaMetrics.

Проблема: WireGuard через границу РФ подпадает под блокировки. Хендшейк
`wgmgmt` между entry и экзитом не встаёт (подпись: обе стороны шлют
инициации 148 Б и ответы 92 Б, сессия не устанавливается, `latest-handshake=0`),
метрики с экзита не приходят, и панель через 3 минуты метит ноду офлайн —
хотя сам VPN через этот экзит работает.

Экзит уже держит Hysteria2-сервер (UDP/QUIC, устойчив к DPI), а entry уже
имеет к нему Hysteria2-аутбаунд для пользовательского трафика. Значит
служебный скрейп надо пустить по Hysteria2 и убрать WireGuard-mesh совсем.

## Что реально ходит через границу

Единственный служебный поток entry↔экзит — скрейп `node_exporter` (порт
`9100`) с entry на каждый экзит (`25-monitoring.sh`). Всё остальное, что
привязано к `10.99.0.x`, живёт НА самой entry и границу не пересекает:

- clash-api sing-box — слушает `10.99.0.1:9090`, читают его панель и
  `failover-watchdog`, оба на entry;
- AdGuard DNS — `10.99.0.1:53`, для VPN-клиентов;
- панель — переменные `NUXT_CLASH_API_URL`, `NUXT_WG_DNS`, `NUXT_MGMT_IPS`.

Вывод: заменить надо только трансграничный хоп (скрейп). Локальный адрес
`10.99.0.1` на entry сохраняем — вешаем его алиасом на `lo`, чтобы clash-api,
AdGuard, панель и watchdog не трогать вообще.

## Архитектура

### Отдельный Hysteria2-туннель под служебку

На экзите — отдельный Hysteria2-инбаунд под мониторинг (свой порт, свой
пароль, та же salamander-обфускация и self-signed TLS, что у клиентского).
Он изолирован от пользовательского туннеля: ротация клиентских паролей его
не роняет, а по клиентским кредам метрики не достать.

На entry — на каждый экзит служебный Hysteria2-аутбаунд к этому порту и
локальный SOCKS-инбаунд на `127.0.0.1`, который в него заворачивает.

### Поток скрейпа

```
VictoriaMetrics (entry)
  → 127.0.0.1:100XX (локальный SOCKS-инбаунд sing-box, свой на каждый экзит)
    → hy2-<tag>-mgmt outbound (entry)
      → hy2-mgmt-in inbound (экзит, UDP/QUIC)
        → direct (экзит дозванивается до 127.0.0.1:9100 = свой node_exporter)
```

VictoriaMetrics скребёт цель `127.0.0.1:9100` с `proxy_url:
socks5h://127.0.0.1:100XX` — своим на каждый экзит. Адрес `127.0.0.1:9100`
резолвится и подключается на СТОРОНЕ экзита, поэтому `node_exporter` на всех
нодах слушает только `localhost`.

RU-нода скребётся локально, без прокси.

### Ограничение служебного инбаунда (defense-in-depth)

Маршрут на экзите пускает `hy2-mgmt-in` только на `127.0.0.1:9100`, всё
прочее с этого инбаунда — в `block`. Пароль служебного туннеля есть только у
оркестратора, но экзит не должен становиться открытым прокси даже при утечке.

## Изменения по файлам

Экзит:
- `infra/configs/sing-box-server.json.tpl` — инбаунд `hy2-mgmt-in`
  (порт `MGMT_HY2_PORT`, пароль `HY2_PWD_MGMT`, obfs, TLS); правило маршрута
  `hy2-mgmt-in → direct` только для `127.0.0.1:9100`, иначе `block`; clash-api
  external_controller перевести на `127.0.0.1:9090`.
- `infra/scripts/10-foreign.sh` — генерация `/etc/anysda/hy2-mgmt.pwd`
  (`gen_pwd`), экспорт `HY2_PWD_MGMT` и `MGMT_HY2_PORT` в envsubst; `ufw allow
  <MGMT_HY2_PORT>/udp`; снять старое правило `9090 from 10.99.0.0/24`.
- `infra/scripts/00-bootstrap.sh` — `node_exporter` слушает `127.0.0.1:9100`
  (убрать «rebinds to mgmt-iface in stage 05»).

Entry:
- `infra/lib/gen-router-config.py` — на каждый экзит: аутбаунд
  `hy2-<tag>-mgmt`, локальный SOCKS-инбаунд `mon-<tag>` (`127.0.0.1:100XX`),
  правило маршрута `inbound mon-<tag> → hy2-<tag>-mgmt`. Читает `{TAG}_MGMT`
  и `{TAG}_HY2_MGMT_PORT`.
- `infra/scripts/20-ru-router.sh` — экспорт `{TAG}_MGMT` и порта служебного
  туннеля в генератор; снять ufw-правило mesh `9090 from 10.99.0.0/24`.
- `infra/scripts/25-monitoring.sh` — scrape-конфиг: экзиты через `proxy_url`
  на локальный SOCKS-порт, цель `127.0.0.1:9100`; RU локально.

Служебка/оркестратор:
- `infra/deploy.sh` — `prep_ru_router` дополнительно снимает с экзита
  `MGMT=$(cat /etc/anysda/hy2-mgmt.pwd)`; выкинуть `prep_mgmt_mesh` (обмен
  WG-ключами) и раздачу `peers.env`.
- `infra/scripts/05-mgmt-mesh.sh` — переписать: WG убрать, на entry повесить
  `ip addr add 10.99.0.1/32 dev lo` (идемпотентно); на экзите ничего.
  Стадию в конвейере оставить под тем же именем.
- `infra/scripts/99-verify.sh` — проверку `wgmgmt`-пингов заменить проверкой
  здоровья scrape-целей VictoriaMetrics.
- `infra/envs/all.env` — убрать `MGMT_NET`/`MGMT_PORT`/`MGMT_IP_*` (mesh),
  оставить `MGMT_IP_RU=10.99.0.1` для локальных конфигов entry; добавить
  дефолт порта служебного туннеля `HY2_MGMT_PORT` (напр. `8444`).

Конфиг:
- `config.example.yaml`, `infra/lib/config2env.py`, `setup.sh` — новый
  необязательный `ports.hy2_mgmt`; секция `admin.ssh_pubkey` (см. ниже).

Панель не трогаем: `10.99.0.1` остаётся на entry, статус нод панель считает
по свежести метрик (`useMonitoring.ts`), а не по mesh.

## Вторая часть: VPN2-31 — не запирать себя (вшивается сюда же)

Дефект: `00-bootstrap.sh` выключает парольный вход, как только у оркестратора
есть СВОЙ ключ (`orchestrator_keys`), не проверяя, что на ноде есть ключ
АДМИНА. Если личного ключа админа нет, а ключ/машина оркестратора потеряны —
человек заперт. Ровно это и произошло с NL.

Правка:
- Публичный ключ админа берётся из `config.yaml` (`admin.ssh_pubkey`).
- `deploy.sh` preflight (у оркестратора есть TTY): если ключа в конфиге нет —
  СПРОСИТЬ его один раз, предложив вписать собственный ключ оркестратора;
  сохранить в `config.yaml`.
- Ключ едет на ноды (как `orchestrator_keys`) и мерджится в
  `authorized_keys`.
- `00-bootstrap.sh` выключает `PasswordAuthentication` ТОЛЬКО после того, как
  ключ админа реально лёг в `authorized_keys`. Нет ключа — пароль остаётся
  включённым, деплой печатает громкое предупреждение.

## Проверка

- Полностью изолированный контур собрать негде: у автора правки нет живого
  доступа ни к одной ноде стенда. Сводит и проверяет правку прогон деплоя с
  машины-оркестратора — не автор.
- Гейт до выката: `sing-box check` на сгенерённом `config-base.json` и
  `sing-box check` шаблона экзита; `python3 -c` синтаксис генератора;
  `bash -n` всех правленых скриптов.
- После выката (на стороне оркестратора): `up{host="<tag>"}=1` в
  VictoriaMetrics по каждому экзиту; панель показывает экзиты онлайн; на
  экзите `ss -lun` показывает служебный UDP-порт; `wgmgmt` больше нет.

## Выкатка и оговорка про залоченный NL

Правка выкатывается обычным прогоном деплоя. VPN2-31 закрывает лазейку на
будущее, но НЕ разблокирует уже запертый сейчас NL: чтобы выкатить, машина
оркестратора должна ещё иметь рабочий ключ к экзиту. Если и он потерян — NL
сначала впустить руками у хостера (rescue / пароль в панели), затем прогон.

## Что осознанно НЕ делаем (YAGNI)

- Не строим общий overlay поверх Hysteria2 с сохранением адресов
  `10.99.0.x` на экзитах — единственный трансграничный потребитель это
  скрейп, туннель под него и достаточен.
- Не переносим clash-api/AdGuard/панель с `10.99.0.1` — адрес остаётся
  локально на entry, миграция этих конфигов не нужна.

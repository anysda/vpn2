# Восстановление после аварии

Где поломка, видно по SSH с entry на экзиты: разбор - в
[creation.md](creation.md#разбор-неудачи). Новые серверы берите на
короткий срок и продлевайте только после
[приёмки](creation.md#приёмка).

## Умер экзит

1. Новый экзит, SSH с entry на него проходит.
2. В `config.yaml` на entry у этого экзита сменить `host` и `password`,
   **`tag` оставить**: на тег завязаны предпочитаемый экзит клиентов,
   ручные маршруты, mgmt-адрес и метрики.
3. Убрать тег из `infra/state/excluded-exits.txt`, если он там есть:
   исключённый экзит деплой не настраивает.
4. Полный `./deploy.sh`.

Базу не восстанавливать, профили клиентов не меняются: клиенты подключены
к entry, а не к экзиту.

Если провайдер переустановил ОС на прежнем IP, сменится host key: деплой
остановится и напечатает команду `ssh-keygen -R ...`. Сначала сверьте
отпечаток через консоль провайдера
(`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`), потом выполните её.

## Умерла entry

1. Спросите провайдера, можно ли перенести прежний IP на новую ВМ. Старая
   entry не должна работать параллельно с новой: у них одни секреты, одни
   экзиты и один бот.
2. Нельзя - новый IP: в сохранённом `config.yaml` сменить `entry.host` и
   `entry.password`, A-запись домена направить на новый IP. Это спасает
   только профили с доменом (`entry.public_host` или `panel.domain`),
   профили с IP нужно скачать заново.
3. Дальше по [backup.md](backup.md#восстановление-entry-ноды-с-нуля) с
   одним отличием: восстанавливать архив **до аварии** по имени, а не
   `latest`. `latest` - самый свежий архив, он мог быть снят со сломанной
   или уже с новой пустой entry.

```bash
./deploy.sh backup-list
./deploy.sh restore <архив-до-аварии> --force
./deploy.sh 99-verify all
```

Архив из внешнего хранилища не в S3 скопируйте на новую entry и передайте
`restore` путь к файлу.

## WireGuard после смены IP

Туннель переподключить: имя из `Endpoint` WireGuard разрешает только при
подключении. При `wireguard.split_local: true` (по умолчанию) из
`AllowedIPs` профиля исключён IP entry на момент выдачи, и со старым
профилем трафик к новому IP уходит в сам туннель. Нужен переимпорт:
скачать конфиг заново, ключи не перевыпускать.

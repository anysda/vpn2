# Подбор серверов

Entry и экзиты сначала берите на час с почасовой оплатой: деплой, проверка
по разделу «Приёмка», и только потом оплата на срок. Не хватило часа -
продлите ещё ненадолго, а не сразу на месяц.

## SSH с entry

Главный признак пригодной связки - SSH именно с entry на каждый экзит:

```bash
ssh root@<entry-ip>
ssh -o ConnectTimeout=10 root@<exit-ip> 'echo ok'
```

Доступ к экзиту из дома этого не доказывает: путь от entry идёт через
другую сеть и может резаться там.

- `Permission denied` - сеть есть, не прошла авторизация (пароль root,
  ключ). Это не блокировка.
- Таймаут - пакеты не доходят: смотрите firewall провайдера экзита и
  консоль ВМ в панели провайдера.

Деплой проверяет SSH сам и экзит без SSH не ждёт: печатает `Экзит <tag>
пропущен: SSH недоступен в pre-flight` и идёт дальше без него.

## Приёмка

SSH работает по TCP, а туннель Hysteria2 между entry и экзитом - по UDP,
поэтому одного SSH мало. Связка годится, когда:

1. SSH с entry проходит на каждый экзит;
2. в выводе `./deploy.sh` блок `verify` показывает `hy2-<tag>-direct ...
   RTT=<N>ms ✓` по каждому экзиту, строки `Полностью недостижимые экзиты
   исключены из деплоя` нет, а `./deploy.sh 99-verify all` заканчивается
   `verify done` на каждой ноде;
3. настоящий клиент через каждый экзит (предпочитаемый экзит в карточке
   клиента) по каждому протоколу, который будете выдавать, открывает сайты
   и показывает внешний IP этого экзита.

## Разбор неудачи

| Что видно | Где причина | Что делать |
|---|---|---|
| С entry не виден один экзит | экзит или его сеть | заменить экзит |
| С entry не видны все экзиты, из другой сети видны | entry | искать причину на entry (firewall, консоль), потом менять entry: локацию или провайдера |
| Экзиты не видны ниоткуда | авария у провайдера экзитов | ждать или менять провайдера экзитов; замена entry не поможет |

Новая ВМ в той же сети может унаследовать ту же беду. Если повтор не
помог, меняйте локацию или провайдера, а не ВМ.

## До выдачи профилей

- **Домен.** `entry.public_host` или `panel.domain`, только A-запись, без
  AAAA. Адрес сервера попадает в профили клиентов: с доменом смена IP entry
  обходится сменой A-записи, профили с IP придётся раздать заново.
- **Внешний бэкап и копия `config.yaml`.** Копию снимайте **после**
  первого деплоя: он дописывает в `config.yaml` ключ оркестратора, без
  которого новая entry не зайдёт на экзиты (парольный вход там
  выключается). Там же `backup.passphrase`. Хранение и внешний backend -
  [backup.md](backup.md).
